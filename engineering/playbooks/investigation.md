# Investigation

Read-only. The output is a cited explanation or a recommendation, not a code change.

1. Trace the code the question is about. For "why is it like this" questions, also read `git log`/`git blame`, linked issues and PRs.
2. Write the answer: Overview / Key concepts / How it works / Where things live / Gotchas. A choice between alternatives: a recommendation with a tradeoffs table.

No branch, no PR. If it leads to a code change, hand back to the user and switch to [bug-fix](bug-fix.md) or [feature](feature.md).

**Report:** the answer. For "are we sure?" questions, your real judgment with reasons. Push back if the premise is wrong.
